### The cause

1. The model repeats a call that failed. The rules for loops end 109 tasks. `test-001` and `test-050` repeat `summary =`, although the error names the operator.
2. The model writes more than one call in one output in 134 of 200 tasks. Three tasks reach the step limit with very long outputs: `test-048` (490 calls), `test-073` (545 calls) and `test-089` (539 calls).
3. The model does not use the key from the instruction. For example, `test-032` and `test-104` use the key as text in `summary =`, and `test-008` uses `PROJ-123`.
4. The model searches for a new title in place of `jira_create_issue`. Thus the score of `create` is 0.0.
5. `metrics.json` marks 3 tasks as garbled: `test-109`, `test-165`, `test-190`. Also, the answer of `test-188` has only repeated tokens of the chat template.

3. Find the project and the key with a tool. Do not copy examples from the tool descriptions.

5. Use `jira_create_issue` to create an issue, not a search for the new title.
6. Start each refusal with `ODMOWA:`, and only in the correct cases.
7. Report only what the tools confirm.
