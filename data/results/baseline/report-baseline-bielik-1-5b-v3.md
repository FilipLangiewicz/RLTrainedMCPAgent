### The cause

The parser is correct: the broken calls are real output of the model. The team treats these points as skills that the model does not have:

1. The model writes more than one call in one output in 160 of 200 tasks, although the prompt says "write one line ... and stop". Gemma 4 E2B does this in 4 tasks and E4B in 6 tasks. The later calls cannot use the results of the earlier calls.
2. The generation does not stop at `</tool_call>`. The other families have special tokens for tool calls in their chat templates. Bielik has no such tokens. The team does not add a stop rule, because the training must teach the model to stop after a call. Its effect on the score is not known.
3. The model copies the examples of the tool descriptions. `PROJ-123` is in the issue_key description, and 57 tasks use a key with this project. `customfield_10010` is in the `fields` description, and 21 tasks use it.
4. After a broken call, the history shows the call with an empty name. The later calls with an empty name can copy this form.
5. 13 answers contain a made-up `<tool_response>`, for example `test-047`. The model writes a tool result itself and does not stop.

### The refusal score

- The score 0.0 of `refusal` is correct in most tasks. The model tries a made-up tool, or it changes the board (`test-037`, `test-038`, `test-077`, `test-119`, `test-157`).
- Answers with ODMOWA often have the wrong reason: 17 answers start with this word in other tasks, for example after a JQL error.

### Grades that are close

These grades are correct by the rules, but the result is near the expected result:

- `test-078`, `test-158`: the tool did not find the issue or the sprint, and the model reported a failure, but not with `ODMOWA:`.
- `test-159`: the answer has `Odpowiedź:` before `ODMOWA:`. The model also used the made-up key `DT-123` and did no search.

### False reports

Some answers report success when the change did not occur: `test-072`, `test-089`, `test-105`, `test-112`, `test-118`, `test-152`, `test-192`, `test-197`, `test-198`.

Bielik has no native tool calls, so it must learn the format and the tools. Its main problems are different from the problems of Gemma: Gemma often makes no call, and Bielik makes calls that have no sense for the task.

### What SFT and RL must teach

1. Use only the tools of the list, with the arguments of the list.
2. Write one call, then stop and read the result.
3. Use a search to find a key, and do not copy examples from the descriptions.
4. Write JQL in the correct form: `summary ~ "word"`, `labels = x`.
5. Do the change, not only a read. Use the tool that does this change.
6. Start each refusal with `ODMOWA:`, and only in the correct cases.
